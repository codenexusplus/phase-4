/sp.constitution - Phase 4: Cloud-Native Governance
1. Core Mandate
The objective of Phase 4 is to wrap the Phase 3 Hybrid AI Chatbot into a production-grade containerized environment managed by Kubernetes (Minikube). Every action must follow Spec-Driven Development (SDD): No manual coding, only agentic execution based on documented specs.

2. Global Engineering Principles
Immutability: Containers must be stateless. All persistence (Tasks/Auth) must reside in the external Neon PostgreSQL database.

High Availability: The infrastructure must be designed for redundancy. No single point of failure within the cluster.

Separation of Concerns: Frontend, Backend, and Database configurations must be logically and physically isolated into separate Kubernetes objects.

Security First: No secrets (API Keys, DB URLs) are to be hardcoded in Dockerfiles or Manifests. Use Kubernetes Secrets.

3. Tooling & Agent Workflow
Claude Code: Acts as the Lead Architect. It manages the .sp.plan and coordinates other agents.

Gordon (Docker AI): The primary agent for generating and auditing Dockerfiles. It must optimize for image size and security.

kubectl-ai: The primary agent for generating Kubernetes YAML manifests via natural language prompts.

Kagent: The diagnostic agent. It must be used to verify pod health and troubleshoot deployment failures.

4. Technical Constraints
A. Containerization (Docker)
Backend: Use python:3.11-slim. Ensure PYTHONPATH is handled via ENV to avoid the ModuleNotFoundError.

Frontend: Use node:20-alpine. Implement Multi-stage builds to keep the production image under 200MB.

Connectivity: All containers must communicate via a Docker network during the testing phase (docker-compose).

B. Orchestration (Kubernetes/Minikube)
Replicas: A minimum of 2 replicas for both Frontend and Backend to demonstrate self-healing.

Services:

todo-backend: Internal ClusterIP.

todo-frontend: NodePort or LoadBalancer for external access.

Probes: Implement livenessProbe and readinessProbe for all deployments to ensure cluster stability.

C. Package Management (Helm)
All Kubernetes manifests must be templatized using Helm.

The values.yaml file must be the single source of truth for environment-specific configurations.

5. Success Definitions (The "Brilliant" Criteria)
Self-Healing: If a pod is deleted manually, Kubernetes must automatically recreate it.

Zero-Downtime: The transition from local process to Kubernetes must not break the AI Chatbot logic or the Dashboard sync.

Agentic Traceability: Every infrastructure change must be traceable back to a /sp.tasks entry.

6. Prohibited Actions
❌ No sudo or manual editing of YAML files generated by agents.

❌ No hardcoded IP addresses. Use Kubernetes DNS (e.g., http://todo-backend:8000).

❌ No manual path setting (e.g., $env:PYTHONPATH). This must be baked into the Docker image.
